## The working method (user's choice — keep it)

Work the **defect backlog one question at a time**: the user names a question; you trace the run-I answer and
spans, compare with a baseline run that did better, check the notes and the graph, find the failing stage,
propose a fix at the right layer, and act after the user picks. Layers, in order of preference:

1. **Tier error** — the expected answer contradicts the notes (brain01 Q28's old must-not). Fix in the vault's
   questions file, with the user's yes.
2. **Data / curation** — fragmented entities, wrong supersession (merge via `same_as.yaml` / `sameas`, dry run
   first; `ingest unsupersede` / `supersede`).
3. **Tool** — a command should report a fact it knows (`complete`, `partial`, `cut`, a `next` signpost) or offer
   a mode (`--via mentions`, `--from/--to`). Facts about the result, never about the question; no routing.
4. **Skill** — only judgement the tool cannot carry; prefer one general rule over a per-command one.

Then **rerun that one question alone** and grade it with Sonnet, update the backlog row (status + notes), and
commit. When a fix needs an enhancement on the work plan, build it then; when the backlog pass is done, finish
the remaining plan items (§0.1: run J → promote → composites → P2b → phase 3 → extraction wave).

### Mechanics that took time to learn

- **One-question rerun:** extract the question's block from the vault's questions file into `/tmp/<q>.md`
  (heading `## Qnn — …` through the next `## Q` heading), then
  `curl -s -X POST http://127.0.0.1:<port>/api/benchmark/runs -H 'Content-Type: application/json' -d '{"path":"/tmp/<q>.md","name":"<label>","contract":"orient","backend":"claude-sdk"}'`;
  poll `GET /api/benchmark/runs/<id>` until `completed`. Ports: banking_corpus admin console 8381, brain01 8379
  (find with `pgrep -f "artmind admin-ui"` + `lsof -a -p <pid> -d cwd`).
- **Restart the vault's admin console after any code commit** before a rerun (it serves code imported at start):
  kill that pid, then `cd <vault> && nohup artmind admin-ui --host 127.0.0.1 --port <port> &`.
- **Grade a rerun:** `cd <vault> && env -u ANTHROPIC_BASE_URL -u CLAUDECODE -u CLAUDE_CODE_ENTRYPOINT artmind traces compare --baseline <baseline ids> --variant <run id> --questions <questions file> --judge --grade --model claude-sonnet-5-5 --allowJudge --compact`;
  per-question detail is in the JSON's `detail_file` (private, in the vault's `.artmind/logs/`). Baselines:
  banking `61cf661f,15837ded,f03056a8` (`benchmarking/questions.md`); brain01
  `49bc9ef6,d6c41e2c,7a1d832d,a984341d` (`benchmarking/Benchmarking_questions_v2.md`).
- **Spans of a turn:** `benchmark_questions` (run_id, qid → trace_id) and `trace_spans` (command, args, rows,
  exit_code, evidence) in `<vault>/.artmind/data/document_registry.db` (open read-only).
- **Live checks:** always `ARTMIND_NO_PROXY=1 artmind …` from inside the vault.
- **Curation:** a one-pair merge without an LLM: write `{"proposed_merges": {"<alias name>": "<canonical>", "<canonical>": "<canonical>"}}`
  and `artmind ingest refine-graph --domain <d> --fromFile <file>`, then `artmind sameas approve <id> --dryRun`
  and approve. If the canonical is already in a group, add the member to that group in `.artmind/same_as.yaml`
  by hand and `artmind projection rebuild --domain <d>` (its dry run's "deleted" count includes keys emptied by
  earlier merges — compare with and without your edit). Merges keep the short name only as an alias; resolution
  now matches aliases (`2057ff41`).
- **Implementers:** subagent `sonnet55-implementer`; give it the exact behaviour and tests, tell it never to stage
  `justfile`, and **run new Cypher live yourself** — tests only check query text (a hub query ran out of Neo4j
