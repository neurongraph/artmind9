- The user asked for implementation through **sub-agents on cheaper models**: Sonnet 5.5 for the
  substantive slices, Haiku 5.5 for small mechanical ones. Each slice ran in its own worktree
  (`isolation: worktree`), was reviewed by the main session (read the diff, check one live

  `ARTMIND_NO_PROXY=1`, and once through a test `serve` on a spare port when the change touches
  the proxy path (P57 was only visible through `serve`).

## Setting up the Mac

```bash
git -C ~/projects/artmind9 pull
cd ~/projects/artmind9 && just dev-install
just dev-stop-daemons
```

Then pull each vault's private repo (`brain01`, `nbs_audit_2026` under `~/artmind_vaults/`), and
start one `serve` per vault on its own port with that vault's admin UI pointed at it, from inside
the vault:

```bash
cd ~/artmind_vaults/brain01 && ARTMIND_SERVE_PORT=<port A> artmind serve
```

```bash
cd ~/artmind_vaults/brain01 && ARTMIND_SERVE_PORT=<port A> artmind admin-ui --host 127.0.0.1 --port 8380
```

(and the same for nbs_audit_2026 with another port; or turn on "serve" in the vault's Obsidian
plugin settings and start the admin UI from the plugin). Check each serve's `/health` names its
vault. A UI started without `ARTMIND_SERVE_PORT` runs every query in-process: correct, slower.

Traps (CLAUDE.md §1, §5):
- A running `serve` or UI serves the code it started with; restart after every merge.
- A Claude Code shell exports its own `ANTHROPIC_BASE_URL`; any artmind LLM call run from it fails
  with 404 unless `ARTMIND_KG_ANTHROPIC_BASE_URL` is in `~/.artmind/config.env` (set on this
  machine; check the Mac's) or the command is prefixed with `env -u ANTHROPIC_BASE_URL`.
- Harness limits differ by Claude Code version: the SDK's bundled CLI (2.1.218 here) has no
  `bashOutputMaxChars`; the bounded-output design §1 records what was measured.
