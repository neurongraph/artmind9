## A different inference provider: what changes

1. **The judge and grader must be the same model for baseline and variant.** `traces compare` uses `--model` or
   the vault's `ARTMIND_KG_LLM_MODEL` (today `claude-haiku-5-5` via `ibm_ica`, from `~/.artmind/config.env`). If
   the new session's provider or model differs, re-grade and re-judge **all** baseline runs with it first; never
   compare a variant graded by one model against a band graded by another. Spec §3.4 also asks for one Sonnet
   re-judge of a baseline pair before the first gate, to see whether the band narrows.
2. **The gateway trap (CLAUDE.md §5).** A Claude Code shell exports `ANTHROPIC_BASE_URL`; artmind LLM calls from
   that shell then go to Claude Code's endpoint. Run judge/grade/ingest commands as
   `env -u ANTHROPIC_BASE_URL -u CLAUDECODE -u CLAUDE_CODE_ENTRYPOINT artmind ...`, and check `env | grep
   ^ANTHROPIC_` first. If the new provider is set through those variables on purpose, decide explicitly which
   endpoint artmind should use; `ARTMIND_KG_ANTHROPIC_BASE_URL` in the vault config takes precedence over the
   environment for `ibm_ica`.
3. **The benchmark agent's model** (what answers the questions in the admin console) is a separate setting from
   the judge. Keep it the same as runs A/D/G for every variant run, or the baseline is no longer comparable; a
   model change is its own measured step.
4. Everything that sends text off the machine needs consent: `traces compare --judge/--grade` needs
   `--allowJudge` or `ARTMIND_COMPARE_JUDGE=1`; brain01 is a private journal.

## How each slice is run (the loop)

1. **Plan** with the `writing-plans` skill: `docs/superpowers/plans/2026-11-xx-p2-N-<name>.md`, from spec §4.x,
   with the evidence from note 20 and §4.3a. P2-1 first, on its own; spec §4.3 lets P2-2..P2-5 be measured in
   pairs (a failed pair is bisected).
2. **Build** with `subagent-driven-development`: one implementer per task (`sonnet55-implementer` for code,
   `haiku55-implementer` for mechanical/doc tasks), then a spec check and a quality check of each commit. The
   controller reads every diff and runs the tests itself before accepting a report.
3. **Live check** after code: `ARTMIND_NO_PROXY=1 artmind ...` (or `just dev-stop-daemons` and restart `serve`):
   a running daemon serves stale code. Then a smoke run in each vault.
4. **Skill variant:** copy `artmind/skills/artmind-query/` to `artmind/skills/artmind-query-<variant>/`, delete the
   skill text the slice replaces (spec §4.x "Skill text it deletes"), and link it into the vaults
   (`cd <vault> && artmind init`; never run `init`/`setup` from the checkout).
5. **The user runs the benchmark** from the admin console with "Skill variant" = the variant name, one run per
   vault (names like `H`, `H1`); the completed-runs table shows each run's id. Restart the admin consoles first
   (they serve stale code).
6. **Measure:** `traces compare --baseline <all baseline ids> --variant <id> --questions <file> --judge --grade`
   per vault, then `traces misses --run <id>`. Gate (spec §3.4): must-item rate per vault and question group at
   or above the lowest baseline run; no lost must item every baseline run found; nothing materially worse than
   all baselines without a dossier. The user reads the flagged answers.
7. **Record** in a new study note (counts, ids, qids only), commit, and replace the classic skill text only after
   a pass.
