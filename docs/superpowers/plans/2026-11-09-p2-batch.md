# P2 batch (P2-2 … P2-5) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Commands absorb the mechanical rules the classic skill still carries — `next` signposts on empty or thin results, a graph route to superseded history, first-person and twin identity in `entity-resolve`, complete counts, per-period survey, question-ranked hub context — and the `artmind-query-orient` skill variant drops the text each replaces. Measured once, as a batch (parent spec §4.3, revised 2026-11-09).

**Architecture:** Each slice is a small change to an existing command plus its tests; no new command group, no routing in code. Signposts follow the orient spec §1.1 contract: a runnable command string in `next` (or in the error text when a command fails without JSON), always a fact about this result. Identity reimplements the planner's narrator/twin rules in classic code (`artmind/identity.py`) reading `artmind/domain_config.py`; nothing imports `artmind.query_plan`.

**Tech Stack:** Python 3.14, Click, Neo4j (read-only Cypher via `graph_query._run_read_query`), DuckDB (structured store), pytest + `CliRunner`.

**Specs:** parent `docs/superpowers/specs/2026-11-08-classic-baseline-and-skill-simplification-design.md` §4.3, §4.3a (with the 2026-11-09 batch revision); signpost contract `docs/superpowers/specs/2026-11-09-p2-1-orient-design.md` §1.1. Evidence: study notes 20 and 22.

### Task 3: supersession direction from document metadata and `_valid_from` (P2-2b data)

**Files:** Create `artmind/supersession_direction.py`, `test/test_supersession_direction.py`; Modify `artmind/conflicts.py:194, 253-271`, `artmind/temporal.py:729` and the `detect_supersession` loop; Test also `test/test_conflicts*.py`, `test/test_temporal*.py` (existing).

Rule, `decide(a, b) -> (newer, older) | None` where each side is `{id, name, _valid_from, version, meta}` and `meta` is the parsed header table (`Status`, `Supersedes`, `Superseded By`, read with `temporal._find_header_value` from the document body via `temporal._read_doc_body_for`):

1. Explicit links win: if `a.meta["Superseded By"]` names `b` (wiki link stem equals `b`'s stem) or `b.meta["Supersedes"]` names `a` → `(b, a)`; symmetric for the other way. If the two sides claim opposite directions → `None` (ambiguous: never guess).
2. Else explicit status: exactly one side `Status: Superseded` (casefold) and the other `Active`/`Current` → the active one is newer.
3. Else dates: the later `_valid_from` is newer; equal or missing → `None`.
4. Version strings are **not** used (the KYC pair has v2.1 older than v2.0).
