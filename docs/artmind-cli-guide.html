artmind
CLI Reference Guide

Artmind — A Knowledge System That Synchronizes with Your Mind

Artmind is a CLI tool for building, querying, and maintaining a knowledge graph backed by Neo4j and SQLite. It ingests documents, extracts entities and relationships via LLMs, and provides rich graph + vector queries.

Usage: artmind [OPTIONS] COMMAND [ARGS]...
1
Initialize
artmind setup
2
Add Domain Schema
artmind domains add schema.yaml
3
Ingest Documents
artmind ingest sync ./docs/
4
Query
artmind query vector-text "question" --domain mydomain

artmind ingest write-to-graph Write already-extracted KG JSON to Neo4j (re-run after fixing Neo4j issues). no required args ▶
Write already-extracted KG JSON to Neo4j (re-run after fixing Neo4j issues).


Two modes:
Single document: artmind ingest write-to-graph DOCUMENT_NAME --domain DOMAIN
Batch from folder: artmind ingest write-to-graph --folder PATH [--domain DOMAIN]

In single-document mode DOCUMENT_NAME is the registered filename (e.g. myfile.pdf).
In folder mode each immediate sub-folder of PATH that contains a document.json is
written to Neo4j. If --domain is omitted in folder mode, the domain is inferred
from the parent directory name (i.e. PATH is expected to be data/kg/<domain>).
artmind ingest write-to-graph [DOCUMENT_NAME] [OPTIONS]

--domain

artmind ingest pull-kg Pull KG JSON from an external GitHub repo into the local KG directory. --repo, --repo-path, --domain required ▶

Refinement
artmind ingest refine-graph Find similar entity names, merge aliases into canonical entities. no required args ▶
Find similar entity names, merge aliases into canonical entities.


Workflow:
1. Dry-run: artmind ingest refine-graph --dry-run --output merges.json
2. Review merges.json and edit if needed
3. Execute: artmind ingest refine-graph --from-file merges.json
artmind ingest refine-graph [OPTIONS]
Options & Arguments
--domain
TEXT		Restrict to entities in this domain (default: all domains)
--filter
TEXT		Filter entities by name (comma-separated for multiple). Default: all entities in domain
--model
TEXT		LLM model for merge decisions (default: ARTMIND_KG_LLM_MODEL env var)
--threshold
FLOAT		String similarity threshold for clustering (0–1)default: 0.7
--dry-run
FLAG		Compute and write proposals only; do NOT apply merges to Neo4jdefault: False
--output
PATH		Write proposals JSON to this file (default: data/refine/proposed_merges.json)
--from-file
PATH		Skip computation — load proposals from a previous dry-run JSON file and apply them
--allow-cross-domain-merge
FLAG		Allow merging same-named entities across domains (default: skip and report them). Only applies when computing proposals via clustering; has no effect with --from-file, which applies proposals already vetted at dry-run time.default: False
artmind ingest refine-graph --dry-run --output merges.json
artmind ingest refine-graph --from-file merges.json
artmind ingest refine-pipeline Run all refinement steps in dependency order: time → supersession → merge → conflicts → consolidate → embed. --domain required ▶
Run all refinement steps in dependency order: time → supersession → merge → conflicts → consolidate → embed.


Workflow:
1. Propose: artmind ingest refine-pipeline --domain <d> [--domain <d2>]
(time/supersession run for real — additive and idempotent;
merge/conflicts/consolidation produce reviewable proposals;
with 2+ domains, a cross-domain conflicts pass runs after every
domain's own steps — merges land first by construction)
2. Review the report and its merges_*.json / conflicts_*.json; edit if needed
3. Apply: artmind ingest refine-pipeline --domain <d> --from-file <report>
Use --apply to skip the review gate (trusted automation only).
artmind ingest refine-pipeline [OPTIONS]
Options & Arguments
--domain
TEXT		Domain to refine (repeatable; 2+ domains add a cross-domain conflicts pass)required repeatable
--apply
FLAG		One-shot: compute AND apply every step (skips the review gate)default: False
--from-file
PATH		Apply vetted proposals from a prior propose report (pipeline_report.json)
--steps
TEXT		Comma-separated subset of: time,supersession,merge,conflicts,consolidate,embed (canonical order enforced)
--model
TEXT		LLM model for merge/conflict/consolidation calls (default: env)
--mergeThreshold
FLOAT		Similarity threshold for merge clusteringdefault: 0.7
--simThreshold
FLOAT		Similarity threshold for conflict candidate pairsdefault: 0.75
--maxPairs
INTEGER		Cap on conflict candidate pairs per detection pass (bounds LLM cost)default: 200
--sampleConsolidations
INTEGER		Consolidation samples shown per domain in propose modedefault: 3
--consolidateLimit
INTEGER		Cap entities consolidated per domain in apply mode (default: all)
--compact
FLAG		Emit compact JSONdefault: False

artmind ingest refine-pipeline --domain banking --from-file pipeline_report.json

Mark one entity node as superseding another (node-level, not document-level).

Use when a new fact replaces an existing node rather than a property on it
— e.g. a role holder or an address changing. Sets a SUPERSEDES edge and
stamps valid_to/superseded_by/status on the older node; nothing is deleted.
--newer and --older each accept either identifier an agent is likely to
already have in hand: the `node_id` (Neo4j elementId) returned by
`update draft`'s candidates, or the `id` property returned by
`entity-context`/`query graph pattern2`/etc.
